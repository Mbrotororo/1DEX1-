# 1DEX1 SHOP

Сайт-магазин ютубера 1DEX1: моды и ресурс-паки для Minecraft.
Обычные HTML, CSS и JavaScript — без сборки. Сайт работает в двух режимах:

- **с сервером** (папка `server/`): настоящие аккаунты в SQL-базе, подтверждение
  почты кодом из письма, баланс, покупки, товары из базы — см. «Сервер и база данных»;
- **без сервера** — на любом хостинге статических сайтов (например, GitHub Pages):
  всё то же самое, но аккаунты хранятся в браузере посетителя.

Режим определяется сам: если рядом отвечает сервер магазина, сайт работает с ним.

## Как открыть у себя

С сервером (нужен Node.js 22.13 или новее, больше ничего ставить не надо):

```bash
cd 1dex1-shop
npm start
```

Без сервера:

```bash
cd 1dex1-shop
python3 -m http.server 8000
```

Потом открой в браузере `http://localhost:8080` (с сервером) или
`http://localhost:8000` (без сервера). Двойной клик по `index.html` не сработает:
браузер не загрузит скрипты.

## Сервер и база данных

Папка `server/` — сервер магазина на Node.js с SQL-базой (SQLite: база — один
файл `server/data/shop.db`, отдельно ставить ничего не нужно). Он же отдаёт сам сайт.

Что делает сервер:

- **Регистрация с настоящей почтой.** Ник, почта, пароль — и на почту приходит
  6-значный код; пока его не ввести, аккаунт не работает.
- **Один ник — один аккаунт.** Ник, который уже есть на сайте, второй раз
  зарегистрировать нельзя, большие и маленькие буквы не различаются (`RodionDex`
  = `rodiondex`). Уже при вводе ника под полем видно «✓ Ник свободен» или «Этот
  ник уже занят» (`POST /api/nick`). Неподтверждённая регистрация держит ник
  сутки, потом он освобождается. Без сервера (превью сайта) аккаунты живут в
  браузере, поэтому там ник проверяется только среди аккаунтов этого браузера.
- **Защита от ботов при регистрации.** Галочка «Я не робот»: по нажатию браузер
  получает от сервера задачу и за долю секунды подбирает число, при котором
  отпечаток sha-256 начинается с 15 нулевых битов (`GET /api/challenge`, решение —
  в `js/pow.js`). Человеку незаметно, а боту, который регистрирует тысячи
  аккаунтов ради кейсов, — дорого. Задача одноразовая, живёт 10 минут, подделать
  её нельзя (подпись HMAC). Плюс скрытое поле-ловушка (люди его не видят, боты
  заполняют) и не больше 10 регистраций в час с одного адреса.
- **Смена ника — раз в 30 дней.** В профиле «Сменить ник»: новый ник проверяется
  при вводе («свободен / занят»); после смены до следующей можно только через 30
  дней — в профиле написано, с какого числа. Покупки, баланс и ID остаются.
- **Кэшбэк 5%.** С каждой платной покупки (с баланса, потом и картой / по СБП)
  5% суммы возвращается на баланс сайта — видно в окне покупки («Кэшбэк на
  баланс +2,21 ₽») и в истории. Процент — `CASHBACK` в `js/data.js` (0 — выключить).
  За купон из кейса кэшбэка нет.
- **Вход тоже по коду.** Ник и пароль — и на почту снова приходит код, без него
  не войти. Код живёт 15 минут, новый — не чаще раза в минуту, перебор кодов и
  паролей ограничен. После входа сайт помнит игрока 30 дней.
- **Номер игрока.** Каждому выдаётся ID по порядку регистрации: 1, 2, 3… — он
  виден на карточке баланса в профиле.
- **Пароли** хранятся только в виде хэша (scrypt), вход — через защищённую cookie.
- **Баланс, история, купоны, покупки, задания** — в базе. Награду из кейса и
  выполнение заданий решает сервер, подделать их в браузере нельзя.
- **Файлы товаров** отдаются только тем, кто купил.
- Пополнение баланса подключится вместе с платёжной системой (пока его делает
  команда `user topup`, см. ниже).

### Админка (для тебя)

Страница управления магазином прямо на сайте — без команд в консоли. Работает
только с сервером.

1. Зарегистрируйся на сайте как обычный игрок (например, ник `1DEX1`).
2. На сервере один раз выполни `npm run admin -- user admin 1DEX1` — аккаунт
   становится админом (`user unadmin` — забрать права).
3. В профиле появится фиолетовая кнопка **«Админка»**. Остальные её не видят, а
   сервер не пустит в админку никого без этой роли.

Вкладки:

- **Продажи** — выручка за сегодня, 7 и 30 дней и за всё время, сколько игроков,
  последние 50 покупок: кто, что, за сколько, чем платил, с каким промокодом.
- **Товары** — у каждого товара: название и описание (рус./англ.), цена (пусто —
  «Цена позже»), метки (`1.21.11, Fabric`), мод или ресурс-пак, готов или в
  разработке, «эксклюзив до» (дата), порядок в магазине, галочка «Показывать на
  сайте»; кнопки «Загрузить файл» (.jar, .zip, .mrpack, .7z, .rar, до 30 МБ —
  отдаётся только купившим) и «Сменить картинку» (до 5 МБ). «+ Новый товар» —
  создать новый. Видно, сколько раз товар купили и на какую сумму.
- **Промокоды** — создать код: скидка в %, сколько раз всего можно применить,
  до какого дня действует; выключить или удалить. Ниже — как часто применяли
  каждый код (и коды из `js/data.js`, например твой с ником). Код из админки
  главнее одноимённого кода из `js/data.js`: так можно, например, ограничить
  срок старого кода.
- **Игроки** — поиск по нику, почте или ID; баланс, покупки, дата регистрации;
  «Баланс ±» — начислить или списать рубли с комментарием (игрок увидит его в
  истории).

### Уведомления о покупках в Telegram

После каждой покупки бот пишет тебе: что купили, кто (ник и ID), за сколько и
чем, промокод, кэшбэк и сколько продаж сегодня. Настройка один раз:

1. В Telegram напиши [@BotFather](https://t.me/BotFather) → `/newbot` → он даст токен.
2. В `server/.env` впиши `TELEGRAM_BOT_TOKEN=токен`.
3. Напиши своему новому боту `/start`.
4. Выполни `npm run admin -- telegram chatid` — он покажет строку
   `TELEGRAM_CHAT_ID=…`, впиши её в `server/.env` и перезапусти сервер.
5. Проверка: `npm run admin -- telegram test` — бот пришлёт тестовое сообщение.

Пока токена нет, уведомления просто не отправляются. Если Telegram недоступен,
покупка всё равно проходит — ошибка только пишется в консоль сервера.

### Почта для кодов

Скопируй `server/.env.example` в `server/.env` и впиши ящик, с которого уйдут
письма: подходит Яндекс, Mail.ru или Gmail по SMTP (порт 465). Пароль нужен не
от почты, а «пароль приложения» из настроек безопасности ящика.

Пока почта не настроена, письма не уходят: код пишется в консоль сервера и в
файл `server/data/outbox.log` — удобно для проверки.

### Как добавить товар

Сейчас в магазине три товара (список — `PRODUCTS` в `js/data.js`, картинки — в
`img/products/`): мод **PvP AI**, эксклюзивный **Новогодний мод** (продаётся до
20 февраля включительно) и **Ресурс-пак 1DEX1**. Цены: PvP AI — 29 ₽,
Новогодний мод — 49 ₽, Ресурс-пак 1DEX1 — 19 ₽. Файлы пока не прикреплены.

**Эксклюзив.** Поле `until: 'ГГГГ-ММ-ДД'` (в `js/data.js`) или `--until` (в базе):
на карточке пометки «Эксклюзив» и «До 20 февраля», а после этого дня (по Москве)
товар сам пропадает из магазина и больше не продаётся; у купивших он остаётся
в профиле со скачиванием.

Товары с сервером хранятся в базе. Команды запускаются в папке `1dex1-shop`:

```bash
# перенести в базу все товары из js/data.js (файлы, загруженные через --file, не трогаются)
npm run admin -- product import

# прикрепить файл к товару из списка (остальные поля — как в js/data.js)
npm run admin -- product add --id pvp-ai --kind mod --title "PvP AI" \
    --desc "PvP AI — мод, который анализирует, кто победит." \
    --cover img/products/pvp-ai.webp --price 29 --file ~/mods/pvp-ai.jar
npm run admin -- product add --id new-year-mod --kind mod --title "Новогодний мод" \
    --title-en "New Year mod" --cover img/products/new-year.webp \
    --price 49 --until 2027-02-20 --file ~/mods/new-year.jar

# ресурс-пак за 99 ₽; файл копируется в server/files и отдаётся только купившим
npm run admin -- product add --id rp-night --kind rp --title "Ночной пак" \
    --title-en "Night pack" --desc "Тёмное небо и звёзды" --price 99 \
    --tags 1.21,Optifine --cover img/rp-night.png --file ~/packs/night.zip

# бесплатный мод со ссылкой на скачивание
npm run admin -- product add --id mod-anim --kind mod --title "Анимации" --price 0 --link https://…

npm run admin -- product list            # все товары
npm run admin -- product price rp-night 79
npm run admin -- product hide rp-night   # спрятать (show — вернуть)
```

### Пользователи

```bash
npm run admin -- user list                     # кто зарегистрировался, баланс
npm run admin -- user topup RodionDex 100      # пополнение вручную (пока нет оплаты)
npm run admin -- user credit RodionDex 50 --note "за конкурс"
npm run admin -- user delete Ник --yes          # удалить аккаунт со всеми данными
npm run admin -- user admin 1DEX1               # доступ в админку на сайте (unadmin — забрать)
npm run admin -- telegram chatid                # номер чата для уведомлений
npm run admin -- telegram test                  # тестовое уведомление
npm run admin -- promo hash КОД                 # отпечаток промокода для js/data.js
```

Удалять аккаунт по просьбе игрока обещает политика конфиденциальности — для этого
и есть `user delete`. Без `--yes` команда только покажет, что будет удалено.

### Где запустить сервер

GitHub Pages умеет показывать только файлы, сервер там не запустить. Подойдёт:

- **VPS** (Timeweb Cloud, Selectel, Beget и т.п., от ~200 ₽ в месяц): поставить
  Node.js 22, скопировать папку `1dex1-shop`, запустить `npm start` (лучше через
  `pm2` или `systemd`, чтобы сервер перезапускался сам) и включить https через
  nginx и Let's Encrypt. В `server/.env` тогда `COOKIE_SECURE=1` и `TRUST_PROXY=1`.
- **Хостинг для Node.js** (Render, Railway и похожие) — обязательно с постоянным
  диском для папки `server/data`, иначе база будет стираться.

Резервная копия — это копия файла `server/data/shop.db` (и папки `server/files`).
База, файлы товаров и `server/.env` в git не попадают.

## Важно про режим без сервера

Без сервера аккаунты хранятся в браузере посетителя:

- аккаунт, созданный на телефоне, не виден на компьютере;
- почта не проверяется, ты не видишь, кто зарегистрировался;
- баланс, кейсы и задания живут в браузере, поэтому опытный посетитель может их
  подделать. Для настоящих денег нужен режим с сервером.

## Как менять содержимое

Содержимое лежит в `js/data.js`, все тексты сайта на двух языках — в `js/i18n.js`:

| Что | Где в `js/data.js` |
| --- | --- |
| Ссылки на YouTube и Telegram, личный Telegram для рекламы | `SITE` |
| Визуалы в «Сотрудничестве»: название, сайт, логотип | `VISUALS` |
| Данные продавца для документов: ФИО, ИНН, почта, дата редакции | `LEGAL` |
| Слова в бегущей строке | `MARQUEE` |
| Ежедневный кейс: награды, шансы, как часто | `CASE` |
| Задания за бесплатные кейсы | `TASKS` |
| Товары для режима без сервера | `PRODUCTS` |

### Как добавить товар без сервера

В `PRODUCTS` уже лежит закомментированный пример. Скопируй его внутрь
квадратных скобок, убери `//` в начале строк и поменяй поля:

```js
{
	id: 'mod-kill-animation',   // любое уникальное имя латиницей
	kind: 'mod',                // 'mod' — мод, 'rp' — ресурс-пак
	status: 'ready',            // 'soon' — в разработке, 'ready' — готов
	title: 'Анимация килла',
	titleEn: 'Kill animation',  // для английской версии, можно не писать
	desc: 'Короткое описание в одну-две строки.',
	tags: ['1.21', 'Fabric'],
	price: 99,                  // рубли; 0 — бесплатно; null — «цена позже»
	cover: 'img/kill-animation.png', // картинка 16:10 или null
	link: 'https://…',          // ссылка на скачивание после покупки или null
},
```

Картинки клади в папку `img/`.
