# src/screens — экраны ПК (B2–B7)

Рабочий стол, Minecraft, Discord, OBS. Это чистые функции рисования на canvas: кадр зависит только от
времени `t`, без состояния. Есть две React-обёртки:

- **`useScreenTexture`**: текстура для 3D-монитора (`<Monitor screen={tex} />` из `src/props/pc.tsx`);
- **`<ScreenPOV>`**: экран во весь кадр для DOM-слоя (`Overlay`). Это планы B3, B4 и B6.

Для b-room готов весь сценарий. Время в нём — **локальное время сцены b-room**, его и передавай:

```tsx
import {PC_TIMING, ScreenPOV, drawPC, pcGlowColor, pcPOV, useScreenTexture} from '../../screens';

// World (внутри 3D): монитор показывает то же, что POV
const Desk: React.FC<{t: number}> = ({t}) => {
	const tex = useScreenTexture(drawPC, t);
	const on = smooth(prog(t, PC_TIMING.screenOn, 0.3));
	return <Monitor position={[x, y, z]} screen={tex} on={on} glowColor={pcGlowColor(t)} />;
};

// Overlay: планы B3 / B4 / B6 — экран во весь кадр с наездом камеры
const Overlay: React.FC<SceneProps> = ({t}) => {
	const T = PC_TIMING;
	const pov = (t >= T.b3 && t < 7.2) || (t >= T.b6 && t < T.b7);
	return pov ? <ScreenPOV draw={drawPC} t={t} {...pcPOV(t)} /> : null;
};
```

Проверочная сцена: `npm run shots -- --scene=screens --sheet`. В `src/scenes/_screens` три части:

- 0–7.2 — POV B3→B6;
- 7.2–12 — тот же экран на 3D-мониторе: включение, рабочий стол, игра, Discord;
- 12–16 — герой перед монитором с игрой, поверх видоискатель `Viewfinder` из `core/hud/rec.tsx`.

## 1. Готовый сценарий (`sequence.ts`)

### Таблица времени `PC_TIMING`

Время — локальное время b-room, секунды. Числа взяты из SPEC §3.

| ключ | время | что на экране |
|---|---|---|
| — | < 2.6 | чёрный (монитор выключен) |
| `screenOn` | 2.6 | экран загорается: рабочий стол проявляется из чёрного |
| `desktop` | 2.95 | рабочий стол виден полностью, курсор стоит |
| `b3` | 3.2 | начало плана B3: курсор летит к значку Minecraft |
| `mcClick` | 3.6 | двойной клик по Minecraft: два клика в 3.55 и 3.65, значок выделен |
| — | 3.7–3.8 | окно игры раскрывается из значка |
| `loadFrom` → `loadTo` | 3.8 → 4.6 | экран загрузки: красный фон, блок травы, полоса идёт рывками |
| — | 4.6 | главное меню: панорама, «Minecraft», курсор наводится на «Сетевая игра» |
| `menuClick` | 4.78 | клик «Сетевая игра» → список серверов |
| `rowClick` | 5.0 | клик по строке HolyWorld (белая рамка, на значке стрелка «играть») |
| `connectClick` | 5.2 | клик «Подключиться» → подключение: земля, логотип HolyWorld, бегущие квадраты |
| `connected` | 5.44 | кадр игры: заснеженный спавн |
| `b4` | 5.6 | окно Discord появляется поверх игры: масштаб 0.94→1 за 0.14 с; канал «общий» |
| `voiceClick` | 6.0 | клик по голосовому «запись» → 1DEX1 появляется под каналом, главная область переходит в голосовой вид |
| — | 6.35+ | зелёное кольцо «говорит» мигает, как речь |
| — | 7.2–8.4 | (B5, 3D) на мониторе по-прежнему Discord в голосовом канале |
| `b6` | 8.4 | окно OBS поверх Discord; в превью — кадр игры, курсор летит к «Начать запись» |
| `recClick` | 9.2 | клик → «● Остановить запись» (красная рамка) и пауза рядом; внизу красная точка и `REC 00:00:00` |
| — | 10.2 | счётчик `REC 00:00:01` |
| `b7` | 10.4 | OBS сворачивается (0.18 с), на мониторе снова игра |

Курсор и клики на каждом экране свои. Курсор спрятан на загрузке и при подключении к серверу; по кликам
расходятся «волны».

### Функции

| имя | что делает |
|---|---|
| `drawPC(ctx, t)` | экран ПК в момент `t` по `PC_TIMING`; это `ScreenDraw` |
| `drawB3`, `drawB4`, `drawB6` | то же, но `t` зажато в свой план: B3 — 3.2…5.6, B4 — 5.6…8.4 (включая B5), B6 — 8.4…10.4 |
| `pcPOV(t)` → `{zoom, focus, tilt}` | камера для `ScreenPOV`: наезд в каждом плане (B3 — 1.0→1.1, B4 — 1.06→1.28 к каналам, B6 — 1.08→1.5 к «Управлению» и счётчику REC); точка фокуса на 25–35 % следует за сглаженным курсором, наклон монитора 4°→1.5° с лёгким дрейфом |
| `pcGlowColor(t)` | цвет отсвета монитора под текущий экран: передай в `glowColor` у `Monitor` |
| `pcScreenAt(t)` | какой экран сейчас: `'off' \| 'desktop' \| 'loading' \| 'menu' \| 'servers' \| 'connecting' \| 'game' \| 'chat' \| 'obs'` |
| `makePcScript(timing)` + `drawPcWith(ctx, t, script)` | свой тайминг: `const S = makePcScript({...PC_TIMING, recClick: 9.6}); const draw: ScreenDraw = (c, t) => drawPcWith(c, t, S);`; `pcPOV(t, S)` |

Если сдвигаешь тайминг, держи порядок `screenOn < desktop ≤ b3 < mcClick < loadFrom < loadTo < menuClick <
rowClick < connectClick < connected < b4 < voiceClick < b6 < recClick < b7`. Между кликами нужно 0.15 с
и больше: курсору нужно успеть долететь.

## 2. Текстура для 3D-монитора

```ts
useScreenTexture(draw: ScreenDraw, t: number, opts?: {width = 1280, height = 720, anisotropy = 4, mipmaps = true}): THREE.CanvasTexture
```

- Один холст и одна `CanvasTexture` на компонент. Холст перерисовывается, когда меняется `t`, затем ставится
  `needsUpdate`. Цветовое пространство — `SRGBColorSpace`: цвета совпадают с POV и DOM.
- Хук вызывай **внутри 3D-сцены** (`World`), потому что он использует `useThree`. Шрифт и картинки могут
  догрузиться позже первого кадра вкладки. Тогда хук держит кадр (`delayRender`) и сам перерисовывает 3D-холст.
  Без этого на первом кадре вкладки экран выходил бы пустым.
- Материал экрана — `MeshBasicMaterial({toneMapped: false, map: tex})`. Так сделано в `Monitor` из
  `src/props/pc.tsx`: проп `screen` растягивает текстуру на весь экран 16:9. Для проверок есть простая
  плоскость `<ScreenQuad texture={tex} width={1.2} position rotation brightness />`.
- **Цена при 1920x1080**, на мониторе во время кадра Minecraft: перерисовка с загрузкой в GPU стоит около
  140 мс при 1280x720 с мип-уровнями. Из них около 60 мс уходит на мип-уровни. При 960x540 с мип-уровнями —
  около 65 мс. Монитор мелкий в кадре (общий план) — ставь `{width: 960, height: 540}`. Крупный план без
  POV — `{mipmaps: false}`.

## 3. Экран во весь кадр: `<ScreenPOV>`

Экран снят «камерой»:

- тонкая тёмная рамка монитора и отсвет экрана на стене вокруг него;
- свечение ярких мест, строки развёртки и пиксельная сетка, блик стекла, затемнение к краям экрана;
- медленный наезд к точке, наклон в перспективе, лёгкое дрожание камеры, виньетка кадра.

Это DOM-слой 1920x1080: клади в `Overlay`. Он полностью закрывает 3D. Пока идёт POV, `World` лучше
облегчить: мир под экраном всё равно не виден, а рисуется.

| проп | по умолчанию | смысл |
|---|---|---|
| `draw`, `t` | — | функция экрана и время, которое она получит |
| `zoom` | 1 | 1 — экран с рамкой занимает 84 % ширины кадра; 1.5 — сильный наезд |
| `focus` | `[640, 360]` | точка экрана (логические px 1280x720), к которой едет камера при наезде |
| `tilt` | `[2.5, 1.5]` | наклон монитора, градусы: `[вбок, вперёд]`; `[0, 0]` — без перспективы |
| `shake` | 1 | дрожание камеры (1 ≈ 3 px) |
| `glow` | 1 | свечение экрана и отсвет вокруг, 0..1 |
| `scanlines` | 1 | строки и сетка, 0..1 |
| `brightness` | 1 | яркость экрана (0 — выключен) |
| `opacity` | 1 | прозрачность всего слоя (для перехода) |
| `resolution` | 1920 | ширина холста экрана, px |
| `background` | `#0b0705` | цвет комнаты вокруг монитора |

Склейки, вспышки и затемнения на стыках с 3D делает сцена: `Fade`/`Flash` поверх, или `opacity` у `ScreenPOV`.

## 4. Отдельные экраны

Если нужен свой сценарий, всё рисуется в логических координатах **1280x720**. Холст любого размера 16:9
готовит `paintScreen(ctx, draw, t)`.

| функция | что рисует |
|---|---|
| `drawDesktop(ctx, t, {selected?, hover?, running?, active?})` | обои (зимний пиксельный пейзаж на закате), значки `Minecraft` / `Discord` / `OBS Studio` (центры — `DESKTOP_ICONS`), панель задач |
| `drawTaskbar(ctx, t, state)` | только панель задач |
| `drawMcLoading(ctx, p)` | загрузка игры, `p` 0..1 (`loadingCurve(k)` — прогресс «рывками») |
| `drawMcMenu(ctx, t, hoverMulti, press)` | главное меню (кнопки — `MC_MENU`) |
| `drawMcServers(ctx, t, {selected, hoverRow, hoverConnect, press})` | «Сетевая игра»: HolyWorld (логотип `public/holyworld.png`, `Лайт Анархия · ВАЙП`, `mc.holyworld.ru`, онлайн, зелёный пинг) и ещё две строки без надписей; кнопки — `MC_LIST` |
| `drawMcConnecting(ctx, k)` | подключение: земля, логотип, бегущие квадраты (без текста) |
| `drawMcGame(ctx, t)` / `drawGame(ctx, t, x, y, w, h)` / `renderGame(t)` | кадр игры: заснеженный спавн, фонари, ели, игрок медленно оглядывается. Псевдо-3D на холсте 480x270, растягивается без сглаживания |
| `drawChat(ctx, t, {joined, speaking, hoverVoice, press})` | Discord: `joined` 0..1 — герой заходит в «запись»; `speaking` 0..1 — зелёное кольцо; `speakingAt(t, from)` — «речь» по времени; строка канала — `CHAT_VOICE_ROW` |
| `drawObs(ctx, t, {recFrom, hoverRec, press})` | OBS: запись идёт с `recFrom` (`Infinity` — не начата); кнопка — `OBS_REC_BUTTON`; `recClock(sec)` → `"00:00:01"` |
| `drawCursor(ctx, x, y, press, scale)`, `cursorAt(keys, t)`, `pressAt(clicks, t)`, `drawRipples(ctx, clicks, t)` | пиксельная стрелка, путь курсора по ключам (плавно, с дугой), нажатие, волны от кликов |
| `drawPixelText(ctx, text, x, y, {px, color, shadow, align})`, `pixelWidth(text)`, `pixelWidthOn(ctx, text, px)` | пиксельный шрифт ядра плюс строчная кириллица (`y` — верх заглавной). Пиксель шрифта привязан к пикселям холста |
| `greek(ctx, x, y, maxW, h, color, seed)` | «нечитаемый текст» — плашки-слова на месте второстепенных подписей |

**Тексты.** В кадре только тексты из SPEC §1 и ник `1DEX1`. Есть ещё два служебных места:

- источник `Minecraft` в OBS;
- строка `запись / 1DEX1` в панели голосового канала Discord.

Остальные подписи интерфейсов — плашки `greek`. Числа на экране: онлайн сервера `2187…/5000`, счётчик REC.
Значки упрощённые и свои:

- блок травы;
- фиолетовый «геймпад-смайлик»;
- тёмный круг с тремя точками;
- кнопка «Пуск» — голубой круг.

**Шрифты и картинки.** Discord, OBS и подписи рабочего стола набраны шрифтом Inter из `public/fonts`:
латиница и кириллица, начертания 300–700. Интерфейс Minecraft использует пиксельный шрифт ядра.
`useScreenAssets()` держит кадр (`delayRender`), пока не загрузятся Inter, `holyworld.png` и `skin.png`; лицо
героя служит аватаром и значком сервера. Его уже вызывают `useScreenTexture` и `ScreenPOV`. Если вызываешь
функции рисования сам, сначала вызови `useScreenAssets()` или дождись `loadScreenAssets()`.

## 5. Замеры

Условия: 1920x1080, одна вкладка, `npm run shots -- --scene=screens --bench`.

| кадр | мс |
|---|---|
| POV (`ScreenPOV`) поверх тестовой комнаты: Minecraft-меню / Discord | ~680 / ~665 |
| то же без POV (тестовая комната + текстура монитора) | ~300 |
| 3D-монитор с перерисовкой текстуры 1280x720 + мип-уровни | ~360 (без перерисовки ~220) |
| то же, текстура 960x540 | ~285 |
| то же, 1280x720 без мип-уровней | ~265 |
| герой + монитор с игрой + `Viewfinder` | ~355 |

POV сам по себе стоит примерно 300–400 мс: холст 1920x1080, эффекты в холсте, наклон в перспективе (~100–170 мс).

Детерминизм проверен так: кадры 2.0, 6.4 и 9.6 отрендерены в разном порядке и в разных вкладках. Они совпали
попиксельно, разница 0.
